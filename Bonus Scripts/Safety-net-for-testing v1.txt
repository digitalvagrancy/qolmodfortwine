SAFETY NET FOR TESTING (Chapbook)
=================================

WHAT IT DOES
Stops the "variable is not defined" error when you test from the middle of the
story. Any variable on the list gets a fallback value of 0 if it hasn't been
set yet. Real values set by your story still take priority.

WHERE IT GOES
Twine > Story > JavaScript. Paste it at the TOP, above any engine.extend code.

THE CODE
--------
// SAFETY NET FOR TESTING
// Gives these variables a fallback value of 0 when they haven't been set yet.
// Chapbook's real values take priority once the story sets them.
// Add a new variable name to this list whenever you create one.
['trust', 'money', 'suspicion'].forEach(name => {
  window[name] = 0;
});
--------

UPKEEP
1. Edit the names in quotes to match your real variables.
2. Keep each name in quotes, separated by commas.
3. Add every new variable name to the list when you create it.

NAMES TO AVOID
Don't put in names JavaScript already uses on the page:
name, status, top, length, event, parent, history

IF SOMETHING GOES WRONG
- If a variable is stuck at 0 after the story sets it, remove this code.
- If {variable} in passage text still errors, text lookups may work differently.
